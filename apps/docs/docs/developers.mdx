Everything needed to build against `zoom-chat-adapter`, on one page: the
credentials, the two files a minimal app is made of, a sandbox for Zoom payloads
and thread IDs, and the machine-readable surfaces that agents and tooling can
read instead of scraping HTML.

## Credentials

This package has no API keys of its own. It authenticates to Zoom with your own
**Server-to-Server OAuth** app, and needs five values:

| Environment variable | Where it comes from |
| --- | --- |
| `ZOOM_CLIENT_ID` | App Credentials in the Marketplace app |
| `ZOOM_CLIENT_SECRET` | App Credentials in the Marketplace app |
| `ZOOM_ACCOUNT_ID` | App Credentials in the Marketplace app |
| `ZOOM_ROBOT_JID` | Team Chat Subscription → Bot JID |
| `ZOOM_WEBHOOK_SECRET_TOKEN` | Features → Access → Token |

```bash .env.local
ZOOM_CLIENT_ID=
ZOOM_CLIENT_SECRET=
ZOOM_ACCOUNT_ID=
ZOOM_ROBOT_JID=
ZOOM_WEBHOOK_SECRET_TOKEN=
```

`createZoomAdapter()` reads all five from the environment. A missing one throws
a `ValidationError` naming the variable, when the adapter is constructed rather
than on the first webhook. To keep secrets elsewhere, pass them explicitly —
see [Configuration](./configuration). [Marketplace setup](./marketplace-setup)
shows where each value lives in the Zoom dashboard.

## The whole app, condensed

Three pieces: an install, a `Chat` instance, and the one route Zoom posts to.

```bash
pnpm add zoom-chat-adapter chat @chat-adapter/state-memory
```

```ts lib/bot.ts
import { createMemoryState } from "@chat-adapter/state-memory";
import { Chat } from "chat";
import { createZoomAdapter } from "zoom-chat-adapter";

export const bot = new Chat({
  userName: "mybot",
  adapters: { zoom: createZoomAdapter() },
  state: createMemoryState(),
});

bot.onNewMention(async (thread) => {
  await thread.post("Hello from Zoom!");
});
```

```ts app/api/webhooks/zoom/route.ts
import { after } from "next/server";
import { bot } from "@/lib/bot";

export async function POST(request: Request) {
  return bot.webhooks.zoom(request, { waitUntil: after });
}
```

Hand the `Request` over untouched: reading the body first breaks the signature
check for every event. A `state` adapter is not optional, since `Chat` connects
to it during initialization. [Quickstart](./quickstart) walks the same path with
the Zoom app and an ngrok tunnel attached.

## Machine-readable surfaces

The docs site publishes the same content for agents, so nothing has to be
scraped out of HTML.

| URL | What it returns |
| --- | --- |
| `/llms.txt` | An index of every page, with one-line descriptions |
| `/llms-full.txt` | The full Markdown of every page in one file |
| `/<route>.md` | Any page's raw Markdown, for example `/quickstart.md` |
| `/<route>` with `Accept: text/markdown` | The same Markdown at the page's own URL, with `Vary: Accept` |
| `/openapi.json` | An OpenAPI 3.1 description of the JSON API below |
| `/api/docs/pages.json` | Every page with its route, title, description, and its Markdown and JSON forms |
| `/api/docs/search?q=` | Full-text search across the docs |
| `/agent-readability.json` | Every agent-facing artifact on this site, in one manifest |
| `/.well-known/agent-skills/index.json` | The Agent Skills this site publishes |
| `/sitemap.xml`, `/robots.txt` | The crawlable URL set and the crawl policy |
| `/404.md`, `/404.json` | The missing-page body as Markdown, and as an RFC 9457 problem document |

A request for a page that does not exist answers `404` in the format the
`Accept` header asks for, so a broken link returns instructions rather than a
page of chrome. The adapter's own package is published on
[npm](https://www.npmjs.com/package/zoom-chat-adapter) and its source lives on
[GitHub](https://github.com/aradhyacp/zoom-chat-adapter).

## Working locally

```bash
ngrok http 3000
```

Use the `https://` forwarding URL as both the Bot Endpoint URL and the event
subscription URL in your Marketplace app. The adapter's own source and the pages
you are reading are in the same repository; `pnpm dev:docs` serves this site on
port 4321.
